# C3 截图 · S0 技术验证记录

2026-11-17 开始。目的：在写 S1 之前确认捕获速度、快捷键和覆盖层路线可行。范围见 [ROADMAP](../ROADMAP.md) 的 C3。

## 环境

- 单台 Apple Silicon Mac，macOS 27.2.1（26B131），Xcode 27.2，SDK 27.2
- 一块显示器：2560×1440 pt，2× 缩放，实际像素 5120×2880
- 探针在本仓库 `build/s0-capture/`（已被 `.gitignore` 排除，不进版本库）。截图只在内存中测量尺寸和时延，不写文件
- 探针以开发会话进程运行，该进程已有屏幕录制授权。**Nivlet.app 自身的授权流程尚未验证**

## 自动测得结果

### 捕获时延（整屏 5K，单屏）

| 方式 | 首次 | 预热后 | 说明 |
| --- | --- | --- | --- |
| ScreenCaptureKit，每次枚举显示器 | 224 ms | 103–109 ms | 其中枚举 `SCShareableContent` 约 36–43 ms |
| ScreenCaptureKit，缓存显示器列表 | — | 66–70 ms | 截完后在后台刷新列表 |
| 旧接口 `CGDisplayCreateImage` | 99 ms | 33–42 ms | 现有 `hs.screen:snapshot` 用的就是它 |

### 冻结覆盖层：从触发到画面显示

程序内触发，含截屏、创建每屏面板、显示冻结画面，不含按键到热键回调这一段。

| 方式 | 第 1 次 | 第 2–3 次 |
| --- | --- | --- |
| ScreenCaptureKit + 缓存列表 | 292 ms | 76–80 ms |
| `CGDisplayCreateImage` | — | 47–72 ms |

### 窗口识别

`CGWindowListCopyWindowInfo` 取当前屏幕窗口：9 个窗口，全部有边界和标题，耗时 19.6 ms。冻结时取一次即可，满足悬停高亮窗口的需求。

### 快捷键

- F1（键码 122）、F3（键码 99）不带任何修饰键，`RegisterEventHotKey` 注册成功
- 系统符号快捷键里的 F1、F3 只出现在带修饰键的组合中，不与无修饰 F1、F3 冲突
- `⌘⇧4` 在系统截图快捷键开启时也能注册成功，但按下时系统会先处理。所以“替代系统截图键”只能提示用户手动关闭系统项，与方案一致
- 本机系统截图快捷键（⌘⇧3/4/5 等）当前全部开启

### SDK 状态

- `CGDisplayCreateImage` 和 `CGWindowListCreateImage` 在 SDK 中标为 `SCREEN_CAPTURE_OBSOLETE(10.6,14.4,15.0)`
- Objective-C 在部署目标 macOS 13 下仍可编译；Swift 直接报“不可用，请用 ScreenCaptureKit”
- 在 macOS 27.2.1 上运行时仍然可用，但随时可能被移除

### 识别文字与二维码（Vision，本机离线）

用合成的 2400×1400 像素图片测试，内容为简中、繁中、日文、英文混排文字和一个二维码，不涉及屏幕内容。

| 项目 | 结果 |
| --- | --- |
| 文字识别，精确模式 | 本机第一次使用 28.8 s（系统一次性准备识别模型）；之后新进程首次 410 ms，再次 218–231 ms |
| 识别质量，精确模式 | 5 行全部识别；仅两处小误差：“S0”识别为“SO”，繁体“歷”识别为日文“歴” |
| 文字识别，快速模式 | 38–67 ms，但中日文全部乱码，**不可用于中文** |
| 二维码 | 70–83 ms，链接完整解出 |
| 支持语言 | 含 zh-Hans、zh-Hant、ja-JP、en-US，覆盖 Nivlet 四种界面语言 |

### 真机按键验证

用电脑控制工具从系统层面发送 F1 键码（与内置键盘按 fn+F1 发出的键码相同），探针设为显示 0.6 秒后自动关闭：

| 项目 | 结果 |
| --- | --- |
| 普通窗口前台按 F1 | 触发；首次 215–255 ms 显示，之后 86 ms |
| 展开菜单时按 F1 | 触发，112 ms；冻结画面完整包含展开的“文件”菜单 |
| 全屏应用里按 F1 | 触发，81 ms；冻结画面为全屏应用本身，覆盖层出现在全屏 Space，没有切走 |
| 覆盖层窗口 | 每次都确认在屏幕上，窗口层级 1000 |
| 焦点 | 覆盖层出现后前台变为截图进程；关闭后需要把焦点交还原应用（S1 处理） |

冻结画面边缘的橙色光晕是电脑控制工具的“正在控制”提示，不是截图功能本身的效果。测试用的缩略图已删除。

## 结论

1. **捕获主路径用 ScreenCaptureKit，并缓存显示器列表。** 预热后从触发到冻结画面约 80 ms，达到 150 ms 目标。旧 CG 接口更快，但已被标为废弃，只作为对照，不作为依赖。
2. **首次触发偏慢（约 290 ms），需要预热。** 做法：启用模块时取一次显示器列表，并预先创建每屏的隐藏面板；显示器变化时重建。预热时不截屏。预热后的首次时延在 S1 实测。
3. **F1 / F3 无修饰键绑定可行。** S1 需要放开 Nivlet 现有校验（目前要求至少一个 ⌃/⌥/⌘，且不支持功能键），只对截图模块开放 F1–F12。
4. **覆盖层走原生 AppKit。** `NSPanel` + `CALayer` 显示冻结画面，预热后 10 ms 级显示，证实不必用 WebView。
5. **普通窗口、展开菜单、全屏应用三种场景都能触发并正确冻结。**
6. **文字识别必须用精确模式**，耗时约 0.2–0.4 s，点按钮后显示进度即可。本机第一次使用要等系统准备模型（这次约 29 秒），界面要给出“正在准备识别…”，不能看起来像卡死。二维码识别 0.1 s 内，可直接用。

## 未覆盖

- 物理键盘上的 fn 组合：测试发的是 F1 键码，等同于 fn+F1 的结果；单按 F1 调亮度是系统行为，没有改动，未单独测
- 截图时菜单栏是否出现系统的屏幕录制提示：电脑控制工具的截图会隐藏测试进程窗口，无法观察
- Esc 关闭：测试中前台是未授权的探针进程，电脑控制工具不允许向它按键，改用自动关闭；Esc 处理代码已写，留到 S1 真机验证

- 多显示器、混合缩放（1× 外接屏 + 2× 内建屏）：本机只有一块屏
- Nivlet.app 自身的屏幕录制授权、拒绝后的提示和重新授权
- 在 Hammerspoon 运行时内集成后的时延（探针是独立进程）
- 中文输入法在覆盖层文字工具中的表现：属于 S1
