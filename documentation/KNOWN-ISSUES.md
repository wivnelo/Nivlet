## 2.0.0 历史范围与兼容性边界

以下保留当时的范围与验收记录，不代替 2.0.1 新包结果。

- 本地文件新增范围仅 HTML/HTM；不新增本地 PDF/TXT/图片/XHTML 或 URL 快捷方式内容解析。原生文档类型注册与实际处理范围的差异，以及冷启动多文件派发仍需单独核查，不宣称通用文件兼容。
- 异常 query 解码空值的稳定性修复纳入本轮审阅；最终回归结果由对应审阅记录给出。
- 新繁中采用台湾用语、香港回退到繁中；日语与繁中不宣称已获母语人工审校。
- 剪贴板快捷键改为固定 ⌘⇧V 的启用开关。新安装/缺失配置默认开启，显式关闭保留；已有自定义组合不能因启动或保存其他页而被覆盖，只有实际切换该开关并保存才改绑固定组合。默认启用、显式关闭、旧自定义与冲突反馈均须纳入最终回归。
- 独立暂停/恢复移除后仅保留历史记录总开关，关闭不删除历史或更改期限。显式持久化的旧 `paused: true` 可迁移为关闭；旧版仅存内存的暂停状态不能跨进程自动读取。替换本机旧版前须检查，若正在暂停，先关闭历史总开关并保存，再退出安装。
- 放大图片预览由点击缩略图或聚焦后按 Enter / Space 打开，已移除独立预览与关闭按钮；仅 Nivlet 窗口内图片元素框外点击关闭，透明像素仍属于图片框。Esc、焦点恢复和防止点击穿透保留；异步历史刷新后焦点恢复已修复，不新增全局鼠标监听权限。
- 原生菜单新增四语言资源，按 macOS 启动语言选择。Toolkit 内切换语言不强制 AppKit 菜单或 Sparkle 对话框即时换语言；这与设置页即时本地化是不同边界。旧 1.0.9 r2 包中四套资源已核验，2.0.0 新包须重新核对；跨系统语言的实际显示不以资源存在代替验收。
- 剪贴板总开关独立卡片、快捷键显示、缩略图交互、三处指定剪贴板说明删除与焦点修复已纳入本次范围；历史 1.0.9 候选的 192 项界面检查和独立 4 项回归通过，不等于 2.0.0 新包已验收。自动回归不等于完整原生端到端验收，保存栏、草稿与其他模块的实际状态见对应验收记录。
- 旧候选测试时菜单 Esc/外部关闭曾受影响；用户手工关闭共享并退出重开后，两种入口均正常关闭。此为用户人工对照，支持远程控制状态干扰的判断；没有菜单产品补丁，不扩展为其他原生场景通过。
- 后续只支持 Apple Silicon；没有 Intel 真机验收，不再发布新的 Intel 包。历史问题及旧版本验证记录如下，不能套用于新候选。

## Issue #1 · FinalShell 规则无法保存（1.0.8 已修复）

FinalShell 的 Bundle ID 为 `st`，旧校验错误要求包含点号。1.0.8 统一前后端 Bundle ID 校验，修复输入法、应用启动、浏览器来源和剪贴板排除规则的相关入口，保留空值、非法字符及长度校验。相关 Lua 与应用更换 JS 回归通过；[Issue #1](https://github.com/wivnelo/Nivlet/issues/1) 已关闭。尚未记录报告者升级后的真实 FinalShell 复验，不将自动回归写成用户确认。

## P2 · 重新授权后的权限状态误报（已修复，继续观察系统差异）

同一进程中，系统信任 API 返回 false，但 Finder AXWindows 成功返回窗口列表，用户确认窗口快捷键仍可用。因此此前 Build 50/51 的“请退出重开”推断过度；当前改用实际跨应用访问核实权限，并移除该提示与额外退出按钮。系统明确报告 API disabled 时仍保持未授权；失败状态与未授权分开。统一窗口保存、配置导入、直接粘贴和界面判断，监听权限变化；保留回到 App 自动检测和“重新检测”。

已在未退出的原进程验证修正后显示已开启，点击重新检测成功。Build 52 安装后权限显示与按钮正常，未操作系统授权。回归涵盖权限撤销/失败、空窗口列表、中英文页面及草稿保护。本轮未重复最新 Intel 包真机运行、再一轮系统开关切换和 Option 粘贴，不能保证任意 macOS 权限异常均可免重开恢复。

从旧 ad-hoc 版迁移到正式 Developer ID 可能需要重新授权一次。正式 54 与 55 的 designated requirement 相同（`dev.local.DesktopToolkit`、同一 Team ID）。Build 55 测试机升级后需重授辅助功能，推测与此前采用 cdhash requirement 的 ad-hoc 开发版有关；两个 Developer ID 正式版之间的权限延续尚未验证。公证本身不授予或保留系统权限。不自动修改 TCC 或删除授权条目。

以下为历史证据，历史的 ad-hoc 状态不适用于 1.0.7。

### 2026-10-14 历史核查


用户在 Intel Mac 替换新版后，从系统权限列表移除旧 Nivlet 并重新添加当前 App，仍需彻底退出重开才恢复；ARM 本机此前重新添加后立即可检测到授权。两台机器的系统版本、重启前实际功能与底层检测值尚未对照，不能确认是 ARM/Intel 差异。

代码核查：两架构使用相同权限逻辑，无按架构分支；每次检测直接调用 AXIsProcessTrustedWithOptions，不是 Nivlet 保存了旧布尔值。但实际 Finder 跨进程探测只在系统先返回已授权时执行，系统返回旧 false 时会跳过探测；这是一处可能的检测盲点，尚不能认定是本次根因。底层 Runtime 还记录部分事件监听可能要授权后重启才能恢复。

后续最小验证：记录两机 macOS、Nivlet 版本；在重新添加权限后/退出重开后分别记录系统信任值、Finder AXRole 探测结果、窗口功能是否可用。先区分显示未刷新与实际功能未恢复，再决定改检测或提供明确的重启引导。禁止假报已授权、绕过 TCC 或自动改系统权限。

本项按用户决定列为 P2，不阻塞本次发布，不影响当前已完成的重复提示修复；无数据丢失证据。仍为 ad-hoc 分发，没有 Developer ID 或 Apple 公证。
